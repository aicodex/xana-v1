# 后台任务等待与结果交付

`harness_sdk/background.py` 的 `BackgroundTasks` 管理 agent_run 与 eval_run 的独立任务、结果和交付状态。会话回答仍由 `TurnCoordinator` 统一执行；后台任务不是另一种对话模式。源码参照见[三家后台任务调研](../exp_ai/harness_background_task_review.md)。

是否委派、等待多久或先回复由模型依据用户意图决定；工具提供能力、参数、状态和结果交付。后台任务文案已在源码中删去额外策略指导，尚未部署；保留文案仍有来源核查项，见[提示词来源约束与本次清单](harness_prompt_assembly.md#提示词来源约束)。功能验收通过不表示这些文案已按上游原文翻译。

## 契约与所有权

- `harness_sdk/contracts.py::TaskNotification` 是完成通知的数据契约。`task_notification_id(task_id)` 定义工具结果、运行中注记和通知入队共用的稳定身份。
- `TaskRecord` 的执行状态与结果由 `BackgroundTasks` 持有，保存在 `background.json`。构造时先恢复登记表，再允许新任务写入，防止启动恢复与新任务互相覆盖；文件损坏明确失败。
- 完成结果交付给持久输入队列后，队列负责保存和消费。`TurnCoordinator` 维护输入及其持久回执；主历史是实际对话内容的权威。
- `ToolResult.background_task_id` 表示该工具结果交回了某个已完成任务。harness 写入主历史后才确认；查询和等待本身不确认交付。

登记表与输入队列各自的职责不同：前者保存任务结果，后者保存已接收的会话工作；没有第二套可写会话历史。

## 等待与停止

`agent_run`、`eval_run` 先等待配置的时长，任务未完成或用户插话时返回任务 ID。已经交出的任务继续运行，`task_wait` 只观察，`task_stop` 明确停止。等待和停止只能操作当前所属会话的任务。

`task_list` 只列当前会话的任务，默认包含运行中或结果尚未交付的记录；可显式查询已交付记录。
主循环仅在任务名单或状态变化时加入简短提醒，压缩丢掉提醒后会重新注入，不依赖模型一直记住任务 ID。

初次委派尚未交出时，取消父回答会停止其直接持有的子任务。`BackgroundTasks.stop` 和硬超时都会等待实际协程完成清理；重复停止不再次打断清理。`Agent.cancel` / `Harness.cancel` 等待指定执行退出，包括已进入最终提交的执行；网关用户停止入口只请求取消，保持立即可达。

临时子 run 或无人值守 run 若试图在其后台任务完成前结束，harness 通过事件等待任务完成、用户输入、维护操作或取消，不用模型反复轮询。后台结果到达后，在下一次模型调用前加入结果。

## 结果进入主循环

父 run 正在执行时，harness 将完成结果写成带固定输入身份的 `background_done` 注记，再确认交付。等待工具直接取得结果时，先写工具历史，再记录该身份的回执并确认任务结果；相应通知不会再重复加入。

父 run 已结束时，通知经 `SessionDelivery` → `AgentGateway.accept` → 当前统一输入队列投递。`accept` 在持久准入后返回，不等待模型整轮完成；网关持有后续事件消费任务，继续向渠道渲染直至结束。它没有独立的回答执行器，实际 run 仍属于同一 control。

自动通知写入历史时保留 `note_kind` 和 `input_id`，正文只包含任务结果，不追加行为指导。`ContextNote` 的稳定输入身份在 SDK 与持久历史转换中保留。队列中尚未消费的用户输入优先于后台通知，各自保持先后顺序。

若进程在历史提交后、回执写入前退出，新 run 从主历史补齐结果回执。已提交的结果不会再次作为新结果追加；不能因此承诺任意崩溃时序下模型请求只执行一次。

## 服务与恢复

serve 在渠道就绪后启动 `retry_notifications`，恢复可投递结果，并每 5 秒重试未接收的通知。重试沿用固定身份，投递失败不确认。退出时先停止该重试任务，再关闭渠道；停机准入与活动执行仍遵守现有统一收尾流程。

`background.json` 使用原有记录格式，写入时临时文件替换并同步文件和目录。确认写入失败会恢复未确认状态。仍在运行的历史记录标为 `interrupted`，不重新运行原任务；新建 agent 任务在启动前就保存子会话 `agent_id`，中断后可以查到原恢复目标。失败报告保留子 agent 已返回的部分文本，不把部分工作误报为成功。

父回答明确取消后，其已交出任务继续运行，完成结果留给用户下一轮，避免自动复活已停止的回答。本次不改变 `/clear` 的结果归属，不增加 Bash 后台执行或账户预算账本。
