# Web 工作台首版实施计划

依据：[用户方向与 Kimi 源码核查](project-capability-design.md#kimi-code-web-源码核查2026-11-09)。该调研已落盘；本文把首版拆成迁移与验收阶段。用户已授权开工，进度见阶段记录；源码完成不表示已经上线。

## 已确认的范围

- Web 为主要工作界面，飞书/TG 保留辅助交互和通知；复用现有单循环执行链。
- 权限仅展示“始终询问、必要时询问、全自动”三档，语义参照 Kimi。用户已确认：**新建会话默认必要时询问**。
- 用户进一步明确权限是**会话级别设置**。选择仅写对应会话；未选择时使用默认值，子 agent 受父会话约束。不引入项目/账户级权限切换，不批量改写旧会话或定时任务配置。
- 用户补充：飞书聊天默认全自动；未选择权限的飞书会话在首条新请求时保存 auto，已有显式选择仍尊重。Web 默认必要时询问不变。
- 首版必须有 goal、checklist、后台 agent 列表、运行中子会话查看、插话、取消和命令日志。
- 子会话可在运行时打开，查看实际派发 prompt、已产生的回答、工具调用、结果与后续变化；查看与执行所有权分开。
- 排除 swarm、tower、完整 TUI 扩建、账户预算账本；此次不重构业务发布系统或替用户修改 demo 工作流。
- 模型自主决定委派、等待时长和先回复还是继续工作；不新增自行编写的调度提示词。

## 实施不变量

1. `boot()` 是组合点；HTTP、Web 和渠道不创建另一套 harness 或上下文生命周期。
2. ContextSDK 继续统一提交模型上下文及压缩变化；Web 只读投影，不改旧消息来拼装页面，不改变模型请求前缀。
3. 权限、goal、清单、后台任务各有唯一权威状态。页面缓存与索引可删除重建，不做双向同步。
4. 插话、停止当前回答、暂停/取消 goal、停止后台任务是不同操作；取消和审批回复不经过等待模型回答结束的文本队列。
5. 页面关闭、切换子会话、SSE 断开仅结束观察。用户明确停止后，goal 不自动复活回答；后台任务沿用当前所有权与结果交付规则。
6. 默认原位替换，旧路径删除才算迁移完成。历史数据先迁移，不删除；不保留旧 attach、占位符或永久兼容枚举。
7. 优先复用现有契约和具体服务，计划不预设新增 ABC。若确需新增，先依 AGENTS.md 说明职责和理由。

## 代码核查所得的迁移边界

| 现状 | 本次落点 |
| --- | --- |
| `runtime/daemon_http.py`拒绝全部 Origin，提供 submit/stream/cancel/button | 在现有 HTTP 服务增加浏览器同源认证、查询与控制入口；继续保留真实 CLI 协议的必要用途，不并存另一套回答执行入口 |
| `DaemonBridgeAdapter`的 SSE ring 是最多 5000 条的进程内缓存，且入口身份是 cli | 整理正式事件来源及订阅作用域，让 Web 与 CLI 观察同一执行；新增快照/持久查询，明确跨重启的游标失效与重新同步 |
| `FileHistoryMirror.compact`替换模型主历史前缀；ContextSDK 保存压缩归档 | 页面不能只读模型主历史作为完整会话。优先复用 `RunJsonlWriter`及 run 索引，核查写入缺口、重复和排序；压缩归档用于必要的历史恢复，不另存一份可写聊天权威 |
| `_RunJsonlMirror`在主历史 append 后写 run 记录，二者有提交失败窗口 | 先验证并修复记录完整性及幂等恢复，再把 run 历史用于 Web。不能仅因为已有 trace_view 就宣称具备可靠浏览器历史 |
| `PermissionMode`声明七个值，实际主链主要使用 default/plan | 盘点生产调用、配置和测试；三档审批与 Plan 只读限制分开表达，显式禁止及子 agent 工具上限仍生效 |
| goal 为 `harness_sdk/goal.py`的额外模型评估 stop-hook | 原位迁移为持久目标和统一循环续跑；清除旧评估器调用与 report_goal 的被替代路径，避免双重续跑 |
| `TodoStore`保存单会话 JSON，harness 通过 metadata 取得对象 | 原位补读取/变化投影与显式依赖注入，Web 与工具共用。子 agent 本就有独立会话，先复用该作用域 |
| `BackgroundTasks`已持久化任务、子会话 ID、结果与交付身份 | 补公开查询与父子关联，保持现有通知去重、取消和重启不重放副作用的规则 |
| `ProcessRunner`读 stdout/stderr 到内存，命令结束后返回 | 执行中保存可读取日志和 offset，模型预览与用户完整日志分开；不把日志展示等同于已具备 Bash 后台执行 |
| 当前每个 project 独立 serve 与认证 | 首版遵守项目隔离。工作区入口导航到对应服务并认证，不让某个项目 token 隐式授权全部工作区 |

## 分阶段工作与完成条件

### 1. 会话查询与事件基础

先检查 `state/interfaces.py`、`memory/interfaces.py`、harness 事件及 `RunJsonlWriter`，建立普通会话和子会话共用的数据契约：会话摘要、父子关系、分页 turns/items、执行状态、版本/游标、缺口与错误。传输实现只消费正式契约；不从其他模块私有字段反推状态。

复用已有 run 记录的稳定身份，补足历史查询和活动执行投影。处理“先读快照后订阅”期间事件遗漏、重复及模型流式内容在重连时恢复的问题。跨进程启动的旧 SSE 游标明确失效，通过完整快照和历史查询重新同步，不能无声接到错误序列。

完成条件：运行中的主/子会话均可分页读取，新增观察者能看到已产生内容；刷新、压缩、服务重启不把完整展示历史替换成摘要。无外部模型调用即可用可控事件验证。

### 2. 三档权限与待审批交互

在现有工具执行边界统一落实策略，工具能力声明与明确禁止仍作为输入；不逐个渠道拼权限规则。新会话默认必要时询问，显式选择持久保存。会话 Plan 状态另存，不能因全自动而意外失去只读限制。

定义实际工具权限矩阵：读取、清单/任务查询、委派、文件修改、命令及外部操作；高危命令分类参照已核查 Kimi 的解析与判定，不能靠少量字符串匹配假装覆盖任意 shell。普通子 agent 权限不高于父级；审批关联 project/session/run/tool call，主界面能处理子 agent 的请求。

待审批操作执行前挂起，支持单次允许、范围明确的本会话批准、拒绝、取消；重复回复与过期回复不得重复执行。切换模式时按执行前最新策略重新判定尚未开始的调用，已执行副作用不回滚；执行时序写入测试。

完成条件：三档矩阵、显式禁止、Plan 约束、子 agent 继承、并发审批、浏览器断线/重连、取消等待与双击审批均通过。无人值守任务遇到必须确认的操作应有可见等待状态和通知，不能偷偷放行。

### 3. 持久 checklist 与 goal

Checklist 复用 TodoStore 和当前会话 ID。补正式读写/事件接口与显式构造注入；压缩时从真实清单产生投影，仍由 ContextSDK 统一提交。清单不是 Plan 审批文件，不保存一份让模型和 UI 分别维护的副本。

Goal 持久保存目标、完成条件、active/paused/blocked/complete 状态、用量和原因；预算继续接现有计量/限制，不引入账本。续跑进入 TurnCoordinator，同一会话只有一个活动执行。用户输入、停止、后台结果与续跑竞争时沿用统一准入及固定输入身份。

按 Kimi 机制处理用户打断、暂停/恢复、预算停止及进程恢复；重启后的目标状态可见，活动执行不自动重放。定时任务继续按现有 scheduler 生命周期运行，不因 goal 规范化为 paused 而被暂停。

完成条件：主/子清单隔离、压缩/重启保留；goal 正常完成、阻塞、暂停/恢复、预算达到、用户插话与停止竞态均通过。删除旧独立评估请求、旧 goal 续跑提示入口及其过时测试；新增模型可见文案须有上游原文与中文对应记录。

### 4. Web 主界面与后台会话

保持一个工作区主视图：左侧工作区/会话，中间主对话和输入区，任务区显示 goal/checklist/后台任务，侧边显示子会话或命令日志。首版子会话面板以查看为主，仍可操作任务停止；不另开完整子 agent 编辑器。

前端拟用 Vue 3 + TypeScript + Vite，便于参照已核查的 Kimi 组件行为；具体版本在实现时核查。前端产物由当前 Python HTTP 服务提供，运行时不额外依赖 Node。工具/日志渲染按正式结构化契约处理，错误明确显示。

浏览器通过带认证的 fetch 订阅 SSE，避免原生 EventSource 无法传 Bearer header 而把长期 token 放进 query。静态页面可加载，API 按项目认证；Origin 校验按同源规则实现，不直接删除保护或开放通配 CORS。新增媒体上传入口沿用现有模型能力和大小限制，不能允许浏览器任意读取服务端 file_path。

输入区在执行中仍可发送和停止；插话采用现有 Xana 语义。任务点击后立即加载子会话快照与实时流，发起 prompt、回答、工具及结果按稳定 ID 合并。用户可以同时查看子执行并继续主会话。

完成条件：真实浏览器覆盖发送、执行中插话/取消、三档切换、审批、goal/checklist、运行中子会话、历史分页和断线恢复。swarm/tower 无入口，无对应新状态机。

### 5. 命令日志与长任务观察

原位扩展 ProcessRunner 的输出保存/通知，保留 stdout/stderr 来源与可续读的字节 offset，支持 tail、分页和实时跟随。日志属于执行记录，查询不发起模型请求；输出上限、保留策略与磁盘错误明确反馈。

取消命令、主回答结束、浏览器关闭均验证资源收尾和日志可读性。此阶段不暗中引入 Bash 后台化；若后续确需改变命令执行所有权，先列出行为差异，再确定范围。

完成条件：大量输出、UTF-8 跨块、刷新续读、日志缺口、取消时保留输出及重启后查询均通过。模型结果预览仍有限，用户日志不以预览的截断文本冒充全文。

### 6. 数据迁移、删除旧路与发布验收

权限按普通会话配置字段实现，不引入强制配置版本升级、权限批量迁移脚本或启动时改写全项目的行为。既有 Plan 标记仍保持唯一持久位置；内部将 Plan 只读约束与三档审批区分，不借此迁移用户配置。

其他确需迁移的 goal/历史数据仍需 dry-run、备份和幂等处理，不运行期间自动改写历史。保留真实 CLI/Feishu/TG 功能所需边界，不把独立渠道误当成需要删除的兼容实现。

删除清单：旧 goal 独立评估链、被替代权限枚举及分支、TODO metadata 隐式注入、被新查询契约替代的页面状态拼装；检查旧 attach/detach/占位回填仍不存在。配置、实现、测试、文档同步更新，不留下另一套旧循环。

完成条件：相关回归和架构检查通过，浏览器端验收通过；隔离项目用真实 Kimi 2.8 验证主/子并行观察、审批、插话、停止、压缩后继续、goal 与后台结果交付，之后清理测试对话记录。2.8 不可用时报告，不替换成 K3。

发布前单独核查生产部署包差异、服务健康、调度文件及下次触发；不将当前工作区全部未提交改动一并同步。上线为后续步骤，本轮规划不重启生产服务。
